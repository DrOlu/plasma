    Changelog¶

    The canonical history lives in CHANGELOG.md. Highlights by release:

    1.29.0 — 2026-11-24¶

    • Estate edge ledger. plasma estate build reduces a bounded window to a small hash-sealed count ledger: users, first/last seen, bounded sources, logon types, user>process pairs and hashes. No command lines, file paths or event rows leave the host.
    • Merge and correlate. estate merge keeps the newest ledger per host and signs the estate view; estate findings raises user fan-out (9 with a shared source, 7 for a same-name pattern), source fan-out, shared file hashes, stale hosts and new host edges against a baseline.
    • Continuous sync. estate sync pulls one ledger per host in parallel over WinRM or files, saves hosts/<name>.json, estate.json and findings.json, records per-host failures without aborting, and supports --loop --interval.
    • Bounded and verified. 200 users, 10 sources per user, 200 process pairs and 256 KiB per host ledger; 5,000 identities on the desk. SHA-256 integrity is verified on load, merge and status.
    • Scale tested. A 1,000-host, 10,000-identity merge and correlation completes in seconds and stays under the estate byte bound.
    • 1051 tests collected; full suite, ruff and bandit (0 medium/high) pass.

    1.28.1 — 2026-11-22¶

    • Responder args from a file. plasma plugin act --args-file reads the JSON argument object from disk, avoiding Windows native-argument quoting when the action takes paths.
    • 1036 tests collected; full suite, ruff and bandit (0 medium/high) pass.

    1.28.0 — 2026-11-22¶

    • Plugin ABI. Four plugin kinds — sensor, detector, responder, exporter — as bounded external processes with a signed manifest, NDJSON contract, per-record validation, quarantine and dedupe. Plugins never write the store directly.
    • Sensor and detector host. plasma plugin run streams events or findings with a hard timeout, line cap, event cap and stderr log; ten invalid records stop the run.
    • Responder actions. plugin act previews exact argv and returns a plan id; apply requires that id and a reason, checks the kill switch and the plugin's enabled state, verifies, journals and supports undo. Paths are checked against declared roots.
    • Ingest and export. JSONL, Windows Event Log and HMAC webhook ingest; batched webhook and syslog export with bounded spooling on failure.
    • Signing and scaffolding. Ed25519 keygen/sign/verify, pinned trust keys, and plugin new for all three plugin kinds.
    • Docs and schemas. docs/plugin-api.md plus manifest and envelope JSON schemas.
    • 1035 tests collected; full suite, ruff and bandit (0 medium/high) pass.

    1.27.7 — 2026-11-22¶

    • TTPForge-driven coverage. Four new baseline rules close the gaps the ForgeArmory run exposed: masqueraded system binaries (T1036.005), PowerShell download via 4104 (WebClient/DownloadFile/Invoke-WebRequest, T1105), WMI reconnaissance via 4104 (Get-WmiObject/Get-CimInstance over Win32_ classes, T1047/T1082) and wmic query reconnaissance (T1047/T1082). Rule count 21 → 25.
    • Query self-match fixed. plasma query --contains X no longer returns the query process's own command line; the current PID is excluded when the image name matches and the row is under five minutes old.
    • Docs corrected to the real baseline count.
    • 995 tests collected; full suite, ruff and bandit (0 medium/high) pass.

    1.27.6 — 2026-11-22¶

    • Defender and ngen parents damped. A final estate pass showed mpcmdrun.exe (Defender) and ngentask.exe scoring at the top for genuinely rare but routine shapes. They join the benign service-parent set.
    • 990 tests collected; full suite, ruff and bandit (0 medium/high) pass.

    1.27.5 — 2026-11-22¶

    • Estate scoring ignores incomplete pairs. An authentication row has a user but no image; the estate component built user> and scored it as first-seen, so 4624 rows topped the ranking at 10.0. Estate components now require a complete image edge or identity pair.
    • 989 tests collected; full suite, ruff and bandit (0 medium/high) pass.

    1.27.4 — 2026-11-22¶

    • Staged installer recognised. The second estate pass showed the release downloaded as plasma-1.27.3.exe in Temp still topping WS2's ranking. The self-filter now also matches plasma-<semver>[-suffix].exe, while look-alike payload names remain scorable.
    • 988 tests collected; full suite, ruff and bandit (0 medium/high) pass.

    1.27.3 — 2026-11-22¶

    • Self-detection tightened. Only the shipped plasma.exe, plasma-<version>-windows-x64.exe and the updater are treated as Plasma's own; a payload called plasma-anything.exe is scored like any other image. Children of Plasma's process tree are damped like other service parents.
    • Second estate pass also confirmed that the injection markers must not be named plasma-* to be visible; that was a test-harness artefact, not a detector rule.
    • 988 tests collected; full suite, ruff and bandit (0 medium/high) pass.

    1.27.2 — 2026-11-22¶

    • Operational self-noise removed. Rows and traces rooted in a plasma*.exe binary are skipped by default, so an upgrade cannot dominate its own anomaly ranking. --include-self restores them.
    • Critical band at 9.0. With service parents damped, genuine first-seen binaries land at 9.1-9.7 again; the band now starts at 9.0 (high 7.5, medium 6.0).
    • 986 tests collected; full suite, ruff and bandit (0 medium/high) pass.

    1.27.1 — 2026-11-22¶

    • Estate calibration. First-run scoring on WS1/WS2 ranked routine servicing (devicecensus.exe, upfc.exe, usoclient.exe and friends) as critical novelty. Children of a small signed service-parent set are now damped by 0.55, and the critical band starts at 9.5 instead of 9.0. Novelty from svchost.exe still surfaces, at triage level rather than red.
    • No raw-data or profile-format change.
    • 984 tests collected; full suite, ruff and bandit (0 medium/high) pass.

    1.27.0 — 2026-11-22¶

    • Behavioural profiles. plasma profile build reduces the bounded local store to counts — images, parent→child edges, identity pairs, destination/registry/file families, command-line shapes and robust hourly volume. Tens of kilobytes, no event rows, no raw command lines, SHA-256 integrity.
    • Explainable anomaly scores. plasma anomaly score|explain fuse categorical rarity, first-seen keys, robust daily volume and optional estate rarity into a 0–10 score with per-component counts. Cold profiles return no score.
    • Causal traces. plasma anomaly trace joins process spans by PID/PPID within one host, handles PID reuse, and scores traces by edge rarity. Traces never cross hosts.
    • Estate tier. plasma fleet profiles builds each host's profile where the data lives and returns only the profile, then merges an estate baseline for cross-host rarity.
    • Credential-safe shapes. net user <name> <password>, --password=... and similar values collapse to <cred> before counting.
    • 982 tests collected; full suite, ruff and bandit (0 medium/high) pass.

    1.26.6 — 2026-11-21¶

    • Two more chain false positives closed. persistence_after_privilege matched any schtasks invocation, so a cleanup schtasks /delete completed the chain; it now requires /create. It also matched Plasma's own scheduled-task registration; events whose parent is a plasma*.exe binary are excluded from that step. Both have regression cases.
    • 957 tests collected; full suite and -W error pass.

    1.26.5 — 2026-11-21¶

    • Chain false positive fixed. persistence_after_privilege matched the bare substring sched, so a read-only Get-ScheduledTask query completed the chain after an unrelated account change and scored 9 — the automatic-containment band. The step now requires schtasks, and a regression case pins the miss.
    • 957 tests collected; full suite and -W error pass.

    1.26.4 — 2026-11-21¶

    • Estate-caught fix. Plasma Sensitive File Delete, Plasma Hidden File Attribute and Plasma Registry Evasion were first cut at criticality 4-5. WHIDS loaded them (281 genes) and then silently dropped every alert, because sensors/whids.toml forwards only criticality > 5. All three now sit at 6.
    • plasma detect validate warns when a gene's criticality is at or below the WHIDS forwarding threshold, so a rule that can never reach the alert log is visible before deployment.
    • Added regression tests for the threshold and the rule set; 957 tests collected.

    1.26.3 — 2026-11-21¶

    • Plasma Encoded Cmd now matches powershell -e <base64> as well as -enc, -ec and -encodedcommand, with a base64-length guard.
    • Added Plasma Sensitive File Delete (T1070.004), Plasma Hidden File Attribute (T1564.001) and Plasma Registry Evasion (T1112/T1564.001). Their criticality was raised to 6 in 1.26.4 after estate testing showed WHIDS drops anything at or below its forwarding threshold of 5.
    • Suppressed PowerShell __PSScriptPolicyTest temp artifacts at info/0.2; they were triggering public-folder and SharePoint Sigma rules on both estate hosts.
    • Extended persistence_after_privilege to recognise sc.exe create and reg add ...\Run, with sequenced regression cases.
    • Added a six-case Atomic Red Team smoke suite: sensors/atomic-smoke.json, tests/test_atomic_fixes.py, docs/atomic-smoke.md.
    • 955 tests collected; full suite and -W error pass.

    1.26.2 — 2026-11-21¶

    • PlasmaWatch, PlasmaWhidsWatchdog and PlasmaCanaryShield now register both an AtStartup trigger and StartWhenAvailable, so enforcement resumes immediately after a reboot or a missed timer run.
    • Added restart-on-failure, MultipleInstances IgnoreNew and execution time limits to the scheduled tasks; a hung sweep can no longer wedge the schedule.
    • PlasmaUpdate remains a daily maintenance-window task; it gains overlap protection and a bounded runtime, not a boot trigger.
    • plasma health now reports present Plasma tasks that lack an AtStartup trigger.
    • 949 tests collected; full suite and -W error pass.

    1.26.1 — 2026-11-21¶

    • Fixed overlapping labels and link paths in the enterprise architecture SVG/PNG; regenerated the product and operations PDFs.
    • No runtime behavior change from 1.26.0.
    • 943 tests collected; full suite and -W error pass.

    1.26.0 — 2026-11-21¶

    • Named-pipe canaries. canary pipe deploy|list|remove|serve|install|uninstall creates decoy pipes and a SYSTEM listener. A client that connects is identified with GetNamedPipeClientProcessId, verified, and killed unless protected/trusted. Enumeration alone does not trigger.
    • Proper architecture diagram. The enterprise AD page now uses a real SVG illustration instead of ASCII art, with a PNG companion for the PDF.
    • Enterprise guide expanded with pipe-canary rollout, scanner caveats and disarm steps.
    • Shield hardening from estate drills: scheduled-task argument quoting, fresh-root Sysmon backup, case-preserving Sysmon conditions, journal ids, DTD/entity refusal.
    • 943 tests collected; full suite and -W error pass.

    1.25.0 — 2026-11-21¶

    • Active canary shield. New plasma canary shield previews/installs a narrow Sysmon FileCreate/FileDelete/RegistryEvent include and a one-minute SYSTEM task. When a process creates, deletes or registry-writes a canary, the sweep verifies the live PID/image, refuses protected/trusted processes and kills the process.
    • Registry canaries. canary registry deploy|list|remove adds decoy keys under Software\PlasmaDecoy in HKCU or HKLM.
    • False-positive boundary. Reads do not trigger; Explorer, Plasma, Defender, backup and system processes are skipped; protected processes are refused. A pure in-place overwrite is still caught by canary verify as a hash change, without process attribution.
    • Enterprise AD deployment guide. Detailed installation, configuration, GPO/SCCM/Intune rollout, fleet, canary shield, SIEM, operations, rollback and troubleshooting for a domain network.
    • 933 tests collected; full suite and -W error pass.

    1.24.1 — 2026-11-20¶

    • ACL intercept refuses without a canary. plasma intercept apply on an ACL rule with no matching canary paths now returns a structured JSON refusal (code: REFUSED) instead of a Python traceback.
    • Invalid summary duration is structured. plasma summarize --since yesterday now returns a JSON query error instead of a traceback.
    • 921 tests collected; full suite and -W error pass; bandit 0 high/medium; pip-audit 0 known vulnerabilities.

    1.24.0 — 2026-11-20¶

    • Opt-in Defender enforcement. New prevent cfa, prevent network and prevent driver-blocklist controls: preview, plan-gated apply, positive verification and rollback by journal id. WDAC remains read-only.
    • Rollback proves the restored value. CFA/Network Protection and the driver-blocklist rollback compare the resulting value with the captured previous value, not just the PowerShell exit code.
    • Actionable posture. prevent posture now says which controls Plasma can apply, gives the preview command and emits a recommendation per gap.
    • Detection regression suite. plasma detect test runs deterministic positive and negative chain cases; a broken expectation exits 2.
    • Security hardening. All outbound downloads are HTTPS-only with no embedded credentials; Sysmon XML refuses DTD/entity input; query regex and detection case files are bounded; MCP get_case no longer writes.
    • Agent surface. MCP adds get_enforcement_posture (20 tools total).
    • 919 tests collected; full suite and -W error pass.

    1.23.0 — 2026-11-20¶

    • Typed investigation. plasma query adds a closed local query language with exact, glob, time, score and aggregate filters. Unknown fields are refused. plasma tree builds lineage only from explicit pid/ppid edges, and plasma summarize reduces a bounded tail to a compact digest.
    • Case workspace. plasma case collects selected events and findings, records notes, renders a timeline and Markdown report, and seals every artifact with a SHA-256 manifest. case verify detects changes.
    • Triggered memory triage. plasma memory triage scans only PIDs selected by injection- or credential-shaped alerts, deduplicated across runs.
    • Identity coverage. 4720/4722/4724/4728/4732/4756/4648/4672-class account, group and privilege events normalize into the event contract. 4662/4672 are supported but excluded from the default high-volume pull. 4688 now retains parent PID for lineage.
    • Detection harness. plasma detect validate|diff|replay compiles rule regexes, compares rule sets by name and hash, and replays chains over a captured store.
    • Tamper and blind-spot accounting. health verifies canary integrity, names blind spots, and includes them in the verdict. prevent posture reads WDAC, Controlled Folder Access, Network Protection and the vulnerable driver blocklist without changing them.
    • Agent surface. MCP adds query_events, get_process_tree, get_summary, get_coverage, get_blind_spots, get_case, scan_memory and simulate_policy. control policy simulate explains a decision without creating an action, approval or ledger row.
    • 900 tests collected; full suite passes.

    1.22.0 — 2026-11-20¶

    • Memory scanning. New plasma memory scan binds HollowsHunter/PE-sieve as a pinned, on-demand probe for hollowing, implanted PEs, shellcode, code patches and IAT hooks. Reports are archived under <root>/memory/; findings become source="memory" alerts.
    • No dumps by default. --dump is explicit and refused with --all; the scanner is SHA-256 verified before execution.
    • JIT noise control. Managed .NET shellcode false positives are suppressed from the alert stream and reported as a count.
    • Bundled and bounded. 64-bit and 32-bit scanners are fetched into the Windows payload; targeted PID/name scans are the default, --all is explicit.
    • Estate-tested on WS1 with a real powershell.exe scan (3.4s deep scan; managed JIT suppressed). 846 tests collected; full suite and -W error pass.

    1.21.0 — 2026-11-19¶

    • Intercept phases 0-3. New plasma intercept surface: shadow rule evaluation over the event store, NTFS deny/audit protection for canary files, a synchronous MCP tool-call gateway, and a native policy broker for ACL and firewall rules.
    • Plan-gated and reversible. Every intercept apply is dry-run first, payload-bound, journaled with an undo recipe, verified, and reversible.
    • No kernel driver. The broker uses gates Windows already owns: NTFS ACLs, Windows Firewall, and the MCP boundary.
    • Estate-verified on WS1 and WS2: shadow matches, canary write denial, ACL rollback, firewall rule apply/rollback, and an MCP INTERCEPTED response.
    • 833 tests collected; full suite and -W error pass.

    1.20.1 — 2026-11-19¶

    • Root help names the token model. plasma --help now says canary files and native DNS/HTTP tokens are normalized into the event store, matching the command help and the 1.20.0 feature set.
    • No behavior change; this is a documentation/help patch on top of 1.20.0.

    • inject-remote-thread compares only the low 32 bits of the target handle, avoiding an untyped 64-bit literal; inject-apc covers the NtQueueApcThread family, including NtQueueApcThreadEx2.
    • Positive controls on WS1 and WS2: local RWX produced self=1 score 5; VirtualProtectEx on a scratch notepad produced self=0 score 8; CreateRemoteThread produced a remote-thread row; QueueUserAPC produced an NtQueueApcThreadEx2 row. All three scripts compile and pass trace selftest on both hosts.
