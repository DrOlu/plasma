    Windows EDR · v1.31.0

    No log lake.
    No cloud.
    No blind trust.

    Plasma keeps the telemetry on the box, answers questions with a 121M on-device model, and makes every response named, journaled, and reversible. The endpoint can explain itself — without shipping its diary anywhere.

    Get started Download v1.31.0 Agent-native operation
    94.6% rollup coverage 13 reversible actions 25 baseline rules 1070 tests Signed MSI + SHA256SUMS
    SENSORS

    Everything stays on the box

    Sysmon, WHIDS gene rules, identity Event Log API, an ETW tap, persistence probes, canaries and DTrace — normalised into one strict JSONL contract.

    ON-DEVICE

    A 121M model that refuses

    Frozen neuralOS instance picks from a closed menu of probes and says unknown when it is — no cloud round-trip, no hallucinated answer.

    ORCHESTRATION

    neuralOSd in front

    An optional local orchestrator with 20 typed probes, a refusal gate and a signed envelope. The model proposes; the operator applies. Read the guide.

    RESPONSE

    Reversible by construction

    Plan-gated actions with single-use approvals, a hash-chained provenance ledger, a kill switch and undo for every change.

    PREVENTION

    Off until you arm it

    enforce contains in seconds; prevent configures AppLocker, firewall egress, ASR, LSA, CFA, Network Protection and the driver blocklist. Dry-run first, journaled, rollbackable — no Plasma kernel driver.

    Detects always. Contains only when armed. Blocks only through Microsoft's own enforcement points.

    Quick start¶

    # 1. download the current release binary
#    https://github.com/DrOlu/plasma/releases/latest

# 2. install (intelligent mode choice: FULL or MINIMAL)
.\plasma-<version>-windows-x64.exe install

# 3. verify
plasma health
plasma identity pull --events C:\ProgramData\Plasma\data\events.jsonl --since 60
plasma watch once

# 4. optional: see what prevention would do (nothing is applied)
plasma enforce run
plasma prevent status
plasma prevent posture
plasma query --kind alert --min-score 0.7 --since 24h

    Every command prints JSON and uses meaningful exit codes, so it composes with Task Scheduler, cron or another agent.

    Why it's different¶

    Commercial EDR ships every event to a central lake and asks you to trust the vendor's console. SIEM does the same one layer up. Plasma starts from the opposite question: what can one machine answer about itself, honestly, without sending its diary anywhere?

    Every other EDR / SIEM Plasma
    Streams events to a vendor cloud Normalizes them on the box into one local JSONL contract
    Central lake required for correlation A desk pulls bounded tails and correlates only when asked
    Model in the cloud decides A 121M on-device model picks from a closed menu of probes
    Response is a vendor API call Response is named, allowlisted and dry-run first; containment is policy-gated; prevention uses Windows enforcement points
    "Trust us" Manifest digests, SHA256SUMS, pinned signer thumbprints, and a refusal gate

    The layers¶

    SENSORS            Sysmon · WHIDS gene rules · Security-log identity ·
                   ETW tap · deep persistence probe · canary tokens · memory scan
EXTENSIONS         plugin sensors · detectors · responders (signed process ABI)
        │
        ▼  one strict event contract (events.jsonl, on the box)
ON-DEVICE BRAIN    frozen neuralOS instance — 10 probes, refuse-if-unknown
        │
        ▼  optional: local model + refusal gate + 20-probe menu
ORCHESTRATOR       neuralOSd — plan/apply/undo over the same typed tools
        │
        ▼  pull-based answers over WinRM/SSM, never a standing server
DESK               status · ask · query · tree · summarize · case ·
                   drift · chains · coverage · fleet ·
                   watch + alerts · plan-gated response (actuate)
        │
        ▼  measured, policy-gated, journaled
PROTECTION         enforce (snapshot + kill at 9+, approval for the rest) ·
                   prevent (AppLocker, egress, ASR, LSA, CFA, Network Protection) ·
                   intercept (NTFS ACL, firewall, agent gateway)

    Estate-wide correlation¶

    The estate edge ledger is the standing counterpart to fleet cases: hosts ship hash-sealed counts, the desk merges and correlates them, and no event diary moves.

    Finding Score Rule
    estate_user_fanout 9 one account on many hosts, with a source address shared across at least two
    estate_user_fanout 7 same-name pattern without a shared source — verify
    estate_source_fanout 9 one source address across many hosts
    estate_stale_host 8 ledger older than --max-age
    estate_hash_fanout 8 the same file hash on many hosts
    estate_new_host_edge 7 user/host pair absent from the baseline
    estate_identity_blind 9 identity pull failed, or the feed stopped inside the window
    estate_identity_unverified 7 other telemetry flowed but there is no identity evidence
    estate_no_telemetry 8 the host reported zero rows 
    plasma estate sync --inventory inventory.json --out-dir C:\PlasmaEstate --loop
plasma estate findings --ledger C:\PlasmaEstate\estate.json

    See Estate edge ledger.

    Plugins¶

    Plasma plugins are bounded external processes with a signed manifest and an NDJSON contract — the same pattern already used for Sysmon, WHIDS, the ETW tap and DTrace. They can be written in any language and installed without rebuilding Plasma.

    Kind What it contributes Command
    Sensor PlasmaEvents from an app, log or agent plasma plugin run
    Detector Findings over a bounded event tail plasma plugin run
    Responder Named actions with preview/apply/rollback plasma plugin act
    Exporter Reserved for plugin-driven outbound sinks —

    The core validates every record, stamps the source, quarantines garbage and keeps ownership of the event store and the response plan gate. Plugins never write events.jsonl directly and never get a shell.

    plasma plugin new acme --kind sensor --out C:\build
plasma plugin keygen --out keys
plasma plugin sign --plugin C:\build\acme --key keys\plugin-private.pem
plasma plugin install C:\build\acme --pubkey keys\plugin-public.pem --enable
plasma plugin run acme --max-events 100

    Inbound adapters bring other systems in: plasma ingest jsonl|evtx|webhook. Outbound adapters push bounded batches: plasma export webhook|syslog. See Plugins for the manifest, protocol, lifecycle, security model and schemas.

    What's new in 1.31.0¶

    • Fewer false blinds. A host whose last pull answered with events is estate_identity_unverified (7), not blind (9) — the feed is alive even when the correlation window holds no auth rows. Blind now means "the pull failed" or "the feed stopped and the last pull brought nothing".
    • Upgrade visibility. estate status lists hosts whose ledger predates coverage blocks under coverage.unknown, instead of silently skipping their checks.
    • Attribution guard. estate sync refuses a remote ledger that names another host or the wrong ledger kind; it becomes a recorded failure, never a merged row.
    • Concurrent-safe writes. All atomic writes (estate, host ledgers, findings, identity marker) use per-process temp names, so two overlapping writers cannot interleave.
    • Cheaper dedupe. identity pull hashes a bounded 64 MB tail instead of reading the whole store, which matters on hosts with large diaries.
    • Robust merges. Malformed ledger sections are skipped instead of crashing merge or findings.

    What's new in 1.30.0¶

    • Quiet is not clean. Every host ledger now carries a coverage block: rows seen, identity and Kerberos counts, last event times, event kinds and the result of the last identity pull.
    • Identity pull marker. plasma identity pull writes identity-pull.json beside the store on every attempt, success or failure, so the desk can tell "the source answered with no events" from "the source could not answer".
    • Coverage findings. estate_identity_blind (9) for a failed pull or an identity feed that stopped inside the window; estate_identity_unverified (7) when other telemetry flowed but there is no identity evidence; estate_no_telemetry (8) for zero rows; estate_kerberos_blind (8) on a declared DC; estate_identity_stale (8) when the pull marker is old.
    • Role-aware. Member servers are not expected to produce 4768/4769; only hosts marked --role dc are checked for Kerberos coverage.
    • One more knob. --max-identity-age (default 180 minutes) controls when a pull marker is stale.

    What's new in 1.29.1¶

    • Remote ledger integrity. estate sync verifies the SHA-256 of every ledger returned by a host before accepting it; a corrupted reply becomes a recorded host failure, not a merged finding.
    • Atomic findings. findings.json is replaced atomically, like estate.json and the per-host ledgers, so a reader never sees a half-written cycle.

    What's new in 1.29.0¶

    • Estate edge ledger. Each host reduces its own store to a small hash-sealed count ledger — users, sources, user>process pairs and hashes, never command lines or file paths. The desk replaces the newest ledger per host, merges and correlates.
    • Continuous sync. plasma estate sync pulls in parallel over WinRM or files, writes estate.json and findings.json, survives a failed host, and runs on a cadence with --loop.
    • Five cross-host findings. User fan-out (9 when a shared source links the appearances, 7 for a same-name pattern), source fan-out, shared file hashes, stale hosts and new host edges against a baseline.
    • Bounded at scale. 200 users and 256 KiB per host ledger; 5,000 identities on the desk. A 1,000-host, 10,000-identity estate merges and correlates in seconds. SHA-256 integrity on every ledger.

    What's new in 1.28.1¶

    • Responder arguments from a file. plasma plugin act --args-file avoids Windows native-argument quoting when an action takes a path.

    What's new in 1.28.0¶

    • Plugin ABI. Sensors, detectors, responders and exporters run as bounded external processes with signed manifests and an NDJSON contract. Validation, quarantine, dedupe and the store stay core-owned.
    • Plan-gated responders. plugin act previews exact argv; apply needs the plan id and a reason, checks the kill switch and journals the rollback.
    • Two-way integration. ingest covers JSONL, Event Log and HMAC webhooks; export covers webhook and syslog with a capped spool.
    • Signed and scaffolded. Ed25519 keygen/sign/verify, pinned keys and plugin new.

    What's new in 1.27.7¶

    • TTPForge-driven coverage. Masqueraded system binaries, PowerShell WebClient/Invoke-WebRequest downloads, WMI reconnaissance over 4104, and wmic query reconnaissance.
    • Query self-match fixed. plasma query --contains no longer returns the query process itself.

    What's new in 1.27.1¶

    • Calibrated on a real estate. Routine Windows servicing no longer reads as critical: children of signed service hosts are damped, and the critical band starts at 9.5.

    What's new in 1.27.0¶

    • Profiles, not a lake. Each host keeps a compact behaviour baseline: counts and robust statistics, never event rows or full command lines. Profiles carry an integrity hash and merge into an estate baseline.
    • Explainable anomaly scores. plasma anomaly score fuses rarity, first-seen keys, daily-volume z-scores and optional estate rarity; every result names the counts behind it. Cold profiles return no score.
    • Causal traces. plasma anomaly trace rebuilds PID/PPID trees on one host and scores them by edge rarity. RDP/SMB hops start a new tree.
    • Estate pulls only profiles. plasma fleet profiles builds on the endpoint and moves kilobytes, not telemetry.

    What's new in 1.26.6¶

    • Chain precision, again. schtasks /delete (cleanup) no longer counts as persistence — only /create does — and events spawned by Plasma's own binaries are excluded from the persistence step.

    What's new in 1.26.5¶

    • One fewer chain false positive. A read-only Get-ScheduledTask query no longer completes persistence_after_privilege; the step now requires schtasks.

    What's new in 1.26.4¶

    • Rules that actually reach the alert log. The three new detection rules were raised to criticality 6 after estate testing showed WHIDS silently dropping anything at or below its forwarding threshold of 5.
    • Validation guard. plasma detect validate now warns when a gene's criticality is at or below that threshold.

    What's new in 1.26.3¶

    • Encoded PowerShell coverage. Plasma Encoded Cmd now covers the -e alias as well as -enc, -ec and -encodedcommand, with a base64 guard.
    • More Atomic-driven coverage. New low/medium rules for sensitive-path deletion, attrib +h, and Explorer file-extension/hidden-file registry changes.
    • Less Sigma noise. PowerShell's __PSScriptPolicyTest temp file is suppressed at info/0.2 instead of firing high-criticality public-folder/SharePoint rules.
    • Better chains. persistence_after_privilege now recognises sc.exe create and reg add ...\Run, in addition to scheduled tasks and services.
    • Atomic smoke suite. sensors/atomic-smoke.json, tests/test_atomic_fixes.py and docs/atomic-smoke.md add a six-case release-validation subset.

    What's new in 1.26.2¶

    • Boot-time enforcement. PlasmaWatch, PlasmaWhidsWatchdog and PlasmaCanaryShield now carry both an AtStartup trigger and StartWhenAvailable. A reboot or missed timer run no longer waits for the next interval.
    • Bounded task runs. Restart-on-failure, non-overlapping execution and execution time limits stop a hung sweep from wedging the schedule.
    • Health drift detection. plasma health reports present Plasma tasks that lack an AtStartup trigger.

    What's new in 1.26.1¶

    • Architecture diagram polish. Removed overlapping labels and rerouted the WinRM, optional API and SIEM links in the enterprise illustration; PDFs regenerated. No runtime behavior change.

    What's new in 1.26.0¶

    • Named-pipe canaries. canary pipe deploy|list|remove|serve|install|uninstall adds decoy pipes. The SYSTEM listener gets the connecting client PID with GetNamedPipeClientProcessId, verifies it, refuses protected/trusted processes, and kills. Enumeration alone is not a connection.
    • Proper architecture diagram. The enterprise deployment page now uses a real SVG illustration instead of ASCII art.
    • Enterprise guide expanded with pipe-canary rollout, scanner caveats and disarm steps.
    • 943 tests, full suite and -W error pass.

    What's new in 1.25.0¶

    • Active canary shield. File and registry canaries can now kill the process that writes or deletes them. A narrow Sysmon include feeds a one-minute SYSTEM sweep; the sweep verifies the live PID and image, refuses protected/trusted processes, then kills and journals.
    • No read false positives. Merely opening or reading a canary does not trigger. Explorer, Plasma, Defender and common backup/system processes are skipped; the boundary is explicit.
    • Registry canaries. canary registry deploy|list|remove adds decoy registry keys watched by the same narrow RegistryEvent include.
    • Enterprise deployment guide. A new AD-domain installation, configuration, GPO/SCCM/Intune, fleet, canary-shield and operations guide.
    • 933 tests, full suite and -W error pass.

    What's new in 1.24.1¶

    • Structured refusal for ACL intercept. intercept apply on an ACL rule with no matching canary now returns a JSON refusal instead of a traceback.
    • Structured refusal for bad summaries. summarize --since with an invalid duration returns a JSON query error instead of a traceback.
    • 921 tests, full suite and -W error pass.

    What's new in 1.24.0¶

    • Opt-in Defender controls. prevent cfa, prevent network and prevent driver-blocklist now preview, apply, verify and roll back with the same plan gate as AppLocker and ASR. WDAC stays read-only.
    • Rollback that proves itself. The previous value is captured at apply time and rollback verifies the restored value, not just the command exit.
    • Detection regression suite. plasma detect test runs deterministic hit/miss cases for phishing, brute force, Kerberos spray, privilege to persistence, account creation and injection.
    • Hardened network fetches. Every download is HTTPS-only, with no embedded credentials or control characters.
    • True read-only MCP reads. get_case renders in memory and no longer writes a report file.
    • 919 tests, full suite and -W error pass.

    What's new in 1.23.0¶

    • Typed investigation. plasma query is a closed local query language; plasma tree follows explicit PID lineage; plasma summarize produces a bounded digest for agent context.
    • Case workspace. plasma case collects selected events and findings, records operator notes, renders a report and seals the artifacts with a hash manifest. case verify detects later changes.
    • Triggered memory triage. plasma memory triage scans only PIDs selected by injection- or credential-shaped alerts.
    • Identity coverage. Account creation/enable/reset, group membership, explicit credentials, special privileges and directory access now normalize into the event contract, with parent PID retained on 4688.
    • Detection harness. plasma detect validate|diff|replay compiles rule regexes, compares rule sets and replays chains over a capture.
    • Honest posture. health now accounts for blind spots and canary tamper; prevent posture reads WDAC, Controlled Folder Access, Network Protection and the vulnerable driver blocklist.
    • Agent surface. Eight new typed MCP tools, including query_events, get_process_tree, get_summary, get_case and simulate_policy.
    • 900 tests, full suite and -W error pass.

    What's new in 1.21.0¶

    • Interception phases 0-3. plasma intercept adds shadow rule evaluation, NTFS canary protection, an MCP tool-call gateway and a native ACL/firewall policy broker.
    • Plan-gated and reversible. Every apply is dry-run first, single-use, payload-bound, journaled and reversible. No kernel driver.
    • Estate-verified on WS1 and WS2: canary write denial and rollback, firewall apply/rollback, shadow matches and an MCP INTERCEPTED response.
    • 833 tests, full suite and -W error pass.

    What's new in 1.20.1¶

    • Root help matches the feature set. plasma --help now names canary files and native DNS/HTTP tokens in the intro, not just "canary decoys".
    • No behavior change; this is a help/documentation patch on top of 1.20.0.

    What's new in 1.20.0¶

    • Native canary tokens. File canaries now use randomized, believable documents; DNS tokens are observed through a narrow Sysmon EID 22 include; HTTP tokens use a loopback-first local collector. No Docker, no cloud.
    • One evidence path. DNS/HTTP hits become source="canary" alerts, watch surfaces them, fleet correlates them, and enforcement maps them to approval-gated isolation.
    • Canary accounts are in the sweep. Configure canary.accounts and every watch sweep checks 4624/4625/4771/4776 with deduplication.
    • Field-verified on WS1 and WS2: file deploy/verify/tamper, a real Sysmon EID 22 query, an HTTP collector hit, watch findings, and a real 4625 on a disabled canary account.
    • 823 tests, full suite and -W error pass, ruff check clean.

    What's new in 1.19.3¶

    • MSI upgrades converge the running node. The package now runs install --force --rotate, which swaps bin\plasma.exe and restarts the registered tasks after staging the new version. Before this, an MSI upgrade updated the files and config but left the service on the old binary.
    • Rotation is all-or-nothing. A failed canonical swap returns exit 4 with the rotation detail instead of reporting a successful install.
    • Verified on WS2: silent MSI install exits 0, bin\plasma.exe --version and /healthz both report 1.19.3.
    • 788 tests, full suite and -W error pass, ruff check clean.

    What's new in 1.19.2¶

    • The MSI is now Authenticode-signed in the release workflow, using the same PFX and timestamp as the exe. SHA256SUMS covers the signed MSI.
    • The MSI is built with -arch x64, so it installs under C:\Program Files\Plasma instead of Program Files (x86).
    • Verified on WS2: silent MSI install exits 0, the installed exe and /healthz report 1.19.2.
    • 786 tests, full suite and -W error pass, ruff check clean.

    What's new in 1.19.1¶

    • HTTP boundary hardened. Parsed command paths replace text scanning, read-only covers every mutating command, the default key is loopback-only, TLS handshakes run in worker threads, request desync is blocked, output is read under a hard byte cap, and mutations fail closed when auditing fails.
    • Response and prevention hardened. Kill switch covers undo and prevention, approvals re-check policy and are atomic, protected paths/processes/tasks are canonicalized, plans are identity- and time-bound, capture failure gates automatic kills, and prevention rollback is plan-gated and verified.
    • Collection and data hardened. Tap/observatory redaction, identity failure reporting, malformed WHIDS/watch rows skipped, content-aware dedupe, trace/MSI validation, deep persistence parsing, BOM-safe stores, canary/fleet/health/Sigma/notify/FIM fixes.
    • Install/update hardened. Dry-run is read-only, operator config is preserved, Sysmon and updates require valid signatures, ring/hold/promote logic is fixed, rotation/rollback/locking is robust, prerelease ordering is correct.
    • Agent trust hardened. Policy type validation, fail-closed tenants, ledger truncation detection, terminal denials and single-use approvals.
    • 785 tests, full suite and -W error pass, ruff check clean.

    What's new in 1.19.0¶

    • Every command has a detailed help page. plasma <command> --help includes a description, working examples, notes, safety, output and related commands. -h works everywhere.
    • plasma help is the discovery command. No topic prints the grouped command map and the dry-run → plan → apply workflow; a topic prints one detailed page.
    • plasma help --json is the machine catalog. Schema plasma.help/1 lists every command path, usage, argument, default, choice, example, safety class and see-also. One topic narrows it.
    • The HTTP API carries the same metadata. /v1/commands rows include summary, description, examples and safety; help --json is runnable through /v1/exec.

    What's new in 1.18.0¶

    • Measured self-update. plasma update auto checks the latest release and applies it through the existing SHA256 + Authenticode + install + rotate path. Signed releases only.
    • PlasmaUpdate daily SYSTEM task with a random minute inside the 02:00–05:00 maintenance window. --no-autoupdate disables it.
    • Ring-aware: broad waits 24 hours; canary updates immediately; rollback never auto-updates. The kill switch pauses updates.
    • Previous binary kept. plasma rollback still restores it; the canonical plasma.exe is rotated and PlasmaServe is restarted after a successful update.
    • update-journal.jsonl and update-state.json record every attempt.

    Doctrine¶

    1. Read-only by default. Collectors read. Manual actions require --apply --plan <id> from a seen dry-run.
    2. Containment is armed but narrow; prevention is audit-first. enforce is limited to snapshot + kill_process at score 9+, with isolation and every other action behind approval. prevent does nothing until you apply a plan. Both are policy-gated and journaled.
    3. Deterministic. Detection is written rules and written chains. The model selects probes; it never decides guilt and never runs commands.
    4. Bounded. Every collector has a time window, a row cap and a size cap.
    5. Local. Events never leave the host by default. The desk pulls what it needs.
    6. Reversible. Every applied action or prevention control carries a journal entry and an undo recipe — where something cannot be undone, the CLI says so up front.
