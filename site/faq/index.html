    FAQ¶

    Is Plasma an EDR?¶

    Functionally yes — endpoint detection and response with sensors, scoring, correlation and containment. Architecturally it deliberately drops the central lake and the always-on vendor console, and it refuses to put the model in the action path.

    Why no central log lake?¶

    Because the questions teams actually ask are about recent, bounded history ("what happened on this box in the last hour?"), and shipping every event to a central store is a large standing cost and a large standing target. Plasma keeps a bounded local diary and pulls only what a case needs. When you do need estate-wide correlation, fleet joins bounded tails on the desk.

    What is actually different from SIEM/SOAR?¶

    SIEM SOAR Plasma
    Data central lake orchestrates other tools bounded local diary per box
    Detection correlation rules in the lake playbooks trigger on alerts written rules + chains over local events
    Response tickets automation with credentials named, dry-run-first, journaled, undoable actions
    Model vendor AI in the cloud n/a 121M on-device router over a closed probe menu

    Can it block or kill automatically?¶

    Yes. There are two tiers. Containment is armed by default but narrow; prevention is audit-first and opt-in.

    • Containment (plasma enforce) reacts to findings in seconds: injection findings first write a host snapshot, then kill the accessing process at score 9+, with a 2-action per-run cap and a 30-minute cooldown. A tripped canary queues host isolation for approval, as do quarantine, disabling users, removing admins, stopping services, credential rotation, task/Run-key/WMI removal and IP blocking. The installer registers PlasmaWatch, which runs the sweep every 5 minutes; plasma protect disarm turns automatic containment off.
    • Enforcement points (plasma prevent) stop behaviour before it runs by configuring AppLocker, firewall egress, Defender ASR and LSA protection. AppLocker starts in audit; every control is dry-run first, plan-gated, verified and rollbackable by journal id.

    How is memory scanning different from Sysmon/ETW?¶

    Sysmon and ETW tell you what a process did. HollowsHunter/PE-sieve looks at what is inside the process now: replaced images, implanted PEs, shellcode, patches and IAT hooks. It is an on-demand, hash-pinned user-mode probe, not a standing monitor. Scan a PID or a small name set; --all is explicit. No dumps are written by default.

    Does interception require a kernel driver?¶

    No. plasma intercept brokers typed rules into NTFS ACLs, Windows Firewall and the MCP tool-call boundary. It does not ship a minifilter, WFP callout or API hook. Kernel-mode malware, malicious drivers and direct syscalls are outside the claim; AppLocker/ASR remain under plasma prevent.

    Do canary tokens need Docker or a cloud service?¶

    No. File canaries are local documents. DNS tokens are read from the local Sysmon channel through a narrow EID 22 include. HTTP tokens are served by plasma canary serve, which binds loopback by default and refuses a non-loopback bind without an explicit flag. There is no container, no external callback and no telemetry endpoint.

    Every apply still passes a dry-run + plan gate, and the kill switch blocks all containment. Plasma does not ship its own kernel driver.

    Does the AI decide anything?¶

    It selects a probe from a fixed menu and fills arguments; it cannot invent tools, read raw logs, or run commands. Detection and correlation are deterministic code.

    Can it run fully offline?¶

    Yes. With internet, the installer provisions Sysmon automatically. Without it, the install degrades to MINIMAL mode (identity + tap) and everything else works from local data.

    Does it phone home?¶

    No. There is no Plasma cloud service. The only outbound update traffic is the release check against GitHub: PlasmaUpdate once a day by default, or an explicit plasma update check / plasma update auto. Nothing else is sent.

    Does Plasma self-update?¶

    Yes, by default. The installer registers PlasmaUpdate, a daily SYSTEM task with a random minute inside the 02:00–05:00 maintenance window. It applies signed releases only, through the same SHA256 + Authenticode + install + rotate path as plasma update apply. broad hosts wait 24 hours after publication; canary hosts update first; rollback hosts never auto-update. The kill switch pauses updates, and the previous binary is kept for plasma rollback. --no-autoupdate disables it; plasma update auto --check-only reports availability without installing.

    How many hosts can a desk manage?¶

    fleet is bounded by your WinRM reachability and the desk's patience, not by a license. Each pull takes a capped tail per host (default 300 rows).

    What about Linux/macOS hosts?¶

    Plasma targets Windows endpoints. The fleet desk runs on macOS/Linux (WinRM client). A Linux sensor is a separate roadmap item.

    Where are credentials stored?¶

    Never in Plasma configs. Inventory uses password_env; notify uses token_env; inline secrets are refused. The desk environment (or your secret manager) holds the values.

    Is the model fine-tunable for my estate?¶

    The supported adaptation is the probe menu, not the weights: add a probe, run the gap loop, re-export the menu, redeploy the same bundle. Weight fine-tuning of the tiny router is not shipped as a supported path.

    Is Plasma signed?¶

    Releases are Authenticode-signed by the project certificate, and update applies are verified against pinned signer thumbprints. Publicly trusted signing (SignPath Foundation) is applied for; SmartScreen reputation builds after approval.

    Is it open source?¶

    MIT. Repository: DrOlu/plasma.

    How do I report a security issue?¶

    Open a GitHub issue for non-sensitive reports. For sensitive ones, contact the maintainer through the address on the repository profile rather than posting details publicly.

    Can I extend Plasma with my own sensor or action?¶

    Yes. Plugins are bounded external processes with a signed manifest: sensor, detector, responder, and the reserved exporter kind. Write one in any language, sign it with plasma plugin keygen and plugin sign, install it with a pinned public key, and enable it explicitly. The core still validates every record, owns the event store and gates response actions. See Plugins.
