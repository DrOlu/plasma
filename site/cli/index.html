    CLI reference¶

    Every command prints JSON. Exit codes are part of the contract: 0 success/clean, 1 data or input error, 2 refused/attention needed, 3 execution or verification failure.

    Help and discovery¶

    Every command has a detailed help page with a description, working examples, notes, a safety classification and related commands. This is the surface an orchestrating agent should use instead of guessing flags.

    plasma --help                      # root overview + agent workflow
plasma help                        # command map, grouped
plasma help control approvals approve
plasma prevent asr --help          # argparse syntax + examples
plasma help --json                 # complete machine-readable catalog
plasma help actuate apply --json   # one command as JSON

    plasma help --json returns schema plasma.help/1: every command path, summary, full description, usage, arguments (required, default, choices), examples, safety class, output and related commands. The same help metadata is included in GET /v1/commands on the HTTP API; an agent can also run POST /v1/exec {"argv": ["help", "--json"]}.

    help¶

    plasma help [topic ...] [--json]

    With no topic, prints the grouped command map and the dry-run → plan → apply workflow. With a topic, prints the same detailed page as plasma <topic> --help. --json returns the catalog, or one command when a topic is supplied. An unknown topic exits 1 with a structured error.

    Endpoint commands¶

    install¶

    plasma install [--dry-run] [--force] [--root PATH] [--skip-whids]
              [--skip-sysmon-check] [--require-whids] [--rotate]

    Intelligent installer: verifies the payload manifest, decides FULL/MINIMAL, installs Sysmon when possible, provisions WHIDS, writes config.json, flips the current junction, and reports the decision. --require-whids makes a degraded decision fail with exit 3. --rotate (used by the MSI) swaps bin\plasma.exe and restarts the registered tasks after staging, so the running node matches the package; a failed rotation exits 4.

    The installer registers PlasmaWatch and PlasmaWhidsWatchdog with both an AtStartup trigger and StartWhenAvailable; PlasmaCanaryShield gets the same pair when armed. A reboot or a missed timer run is picked up immediately. PlasmaUpdate deliberately stays on its daily maintenance window. health reports any present Plasma task that lacks an AtStartup trigger.

    health / status / probe / ask¶

    plasma health [--root PATH]
plasma status [--events FILE]
plasma probe --tool NAME --events FILE
plasma ask --prompt "..." --events FILE

    health = checks + verdict, including whether present Plasma tasks carry an AtStartup trigger. status = bundle identity + probe menu. probe/ask = run one named probe, or let the on-device model choose one. Refusals are structured, never guesses.

    identity¶

    plasma identity pull --events FILE [--host NAME] [--since MINUTES]
                     [--ids LIST] [--max-events N]

    Reads the Security channel through the Event Log API, UTC-normalized, deduped and bounded (--max-events, default 2000).

    Event Kind What it gives you
    4624 / 4625 auth logon success / failure, type, source, workstation
    4768 / 4769 / 4770 / 4771 auth Kerberos TGT, service ticket, renewal, pre-auth failure (KDC only — zero on a member server, reported as zero)
    4776 auth NTLM credential validation
    4688 process process creation with creator subject, parent image and command line (when audit policy records it)

    --ids takes a comma list from that set and is allowlisted: anything else is rejected before PowerShell is invoked.

    whids¶

    plasma whids pull    --root DIR --out FILE
plasma whids push    --events FILE [--min-confidence N] [--max-indicators N] [--apply] [--reason TEXT]
plasma whids status  --root DIR --events FILE
plasma whids diagnose [--root DIR]
plasma whids ensure  [--root DIR] [--wait SECONDS]

    push is dry-run by default; --apply replaces plasma-iocs.gen atomically. Default confidence is 8 on the gene 0–10 scale.

    ensure is the watchdog body: Running is a no-op; a hung StartPending is force-stopped and restarted; a stopped service is started. Actions are appended to logs/whids-watchdog.log. The installer registers PlasmaWhidsWatchdog (SYSTEM, every 2 minutes) to run it.

    trace¶

    plasma trace list
plasma trace check
plasma trace selftest [--root DIR]
plasma trace run <script> --events FILE [--for 5s] [--max-rows N] [--out FILE]
plasma trace provision

    Reviewed, bounded DTrace runs normalized into the event store. provision installs the Microsoft package (direct MSI when winget is absent), enables bcdedit /set dtrace on, and reports reboot_required: true. Installed + enabled is ready; versions are not chased. Scripts emit tid for estate portability.

    tap¶

    plasma tap list
plasma tap selftest [--rules FILE] [--tap-exe PATH]
plasma tap run [--providers LIST] [--for DURATION] [--max-matches N] [--out-dir DIR]

    Bounded live ETW window. Exit 3 = the session could not start.

    deep¶

    plasma deep persistence [--json-out FILE] [--cap N]

    One bounded pass over every auto-start location with Authenticode status.

    watch / notify¶

    plasma watch once [--canary-account ACCOUNT...]
plasma watch loop --every SECONDS [--canary-account ACCOUNT...]
plasma notify show [--root PATH]
plasma notify test [--root PATH] [--host NAME]

    watch = health + drift + canaries + new alerts + chains → verdict; exits non-zero when findings exist. Configured canary accounts live in config.json under canary.accounts; --canary-account overrides them for one invocation. notify validates and tests delivery channels.

    canary¶

    plasma canary deploy [--dir PATH] [--randomize|--no-randomize] [--subdir NAME]
plasma canary verify
plasma canary status
plasma canary token create --kind dns --domain SUFFIX [--out PATH]
plasma canary token create --kind http --base-url URL [--out PATH] [--name NAME]
plasma canary token list
plasma canary token remove ID [--delete-artifact]
plasma canary serve [--host 127.0.0.1] [--port 8088] [--max-requests N]
plasma canary collect [--since MINUTES] [--max-events N]
plasma canary hits [--last N]
plasma canary sysmon [--domain SUFFIX...] [--apply]
plasma canary registry deploy [--hive HKCU|HKLM] [--count N]
plasma canary registry list
plasma canary registry remove ID
plasma canary shield status
plasma canary shield install [--apply --plan ID --reason TEXT]
plasma canary shield uninstall [--apply --plan ID --reason TEXT]
plasma canary shield sweep [--since-minutes N] [--apply --reason TEXT] [--max-kills N]
plasma canary pipe deploy [--count N]
plasma canary pipe list
plasma canary pipe remove ID
plasma canary pipe serve [--apply --reason TEXT] [--max-kills N] [--max-connections N]
plasma canary pipe install [--apply --plan ID --reason TEXT]
plasma canary pipe uninstall [--apply --plan ID --reason TEXT]
plasma canary pipe status

    File canaries are realistic decoys with randomized subdirectories and names by default; the body never identifies itself. verify reports missing or modified files at score 10. DNS tokens are unique hostnames matched from Sysmon EID 22; canary sysmon --apply writes a narrow DnsQuery include and hot-reloads it. HTTP tokens are .url shortcuts served by the local collector; hits are written to <root>/canary-hits.jsonl. watch (or canary collect) turns DNS/HTTP hits into source="canary" event-store alerts, deduplicated across sweeps.

    Registry canaries are decoy keys under Software\PlasmaDecoy in HKCU or HKLM. canary shield install adds only the recorded canary basenames and registry fragments to a narrow Sysmon FileCreate/FileDelete/ RegistryEvent include, then registers a one-minute SYSTEM task. The sweep verifies the live PID/image, refuses protected/trusted processes, kills a process that creates/deletes/registry-writes a canary, and journals the decision. Reads do not trigger; a pure in-place overwrite is detected by canary verify as a hash change without process attribution.

    Named-pipe canaries are decoy pipes. canary pipe install registers a SYSTEM listener at boot; a client that connects is identified by PID and killed after the same protected/trusted checks. Enumeration alone is not a connection and is not killed. Decisions are written to <root>/canary-pipe-journal.jsonl; canary pipe status reports live connection and kill counters while the task runs. The listener is user-mode, not a driver.

    intercept¶

    plasma intercept status
plasma intercept rules list
plasma intercept rules add --file FILE
plasma intercept rules remove RULE_ID
plasma intercept evaluate [--events FILE] [--max-rows N] [--out FILE]
plasma intercept apply RULE_ID [--apply --plan ID --reason TEXT]
plasma intercept protect-canary [--prefix PATH] [--apply --plan ID --reason TEXT]
plasma intercept rollback --id ID [--apply --plan ID --reason TEXT]

    Deterministic policy at native gates. evaluate is the shadow phase: it reports would_block without changing the host. protect-canary adds an NTFS deny/audit ACL to the canary manifest. apply brokers acl and firewall rules. The MCP tool-call gateway evaluates agent_tool_call rules before policy and handlers. Every apply is dry-run first, plan-gated, payload-bound, journaled and reversible.

    acl rollback restores the prior SDDL; firewall rollback removes the named rule. AppLocker and ASR remain under plasma prevent.

    memory¶

    plasma memory scan --pid PID...
plasma memory scan --pname NAME...
plasma memory scan --all [--timeout SECONDS]
plasma memory scan ... [--deep] [--dump] [--scanner 64|32]
plasma memory triage [--since-minutes N] [--min-score S] [--max-targets N] [--no-deep]
plasma memory status
plasma memory list

    Bounded, on-demand HollowsHunter/PE-sieve scan for hollowed or replaced PEs, reflective DLLs, shellcode, code patches and IAT hooks. The scanner is SHA-256 pinned and refuses a mismatched binary. Findings become source="memory" alerts. --dump is explicit, local and refused with --all; no dumps are produced by default. Managed .NET JIT shellcode observations are suppressed from the alert stream. triage scans only PIDs selected by injection- or credential-shaped alerts in the recent window.

    Exit 0 = clean, 2 = findings, 1 = input/tool error.

    investigate¶

    plasma query [--spec JSON|FILE] [FILTERS] [--since 1h] [--count-by FIELD] [--out FILE]
plasma tree [--pid PID | --process NAME] [--depth N] [--max-rows N]
plasma summarize [--since 1h] [--limit N] [--rare-max N]

plasma case open NAME [--host H] [--title TEXT] [--note TEXT]
plasma case list
plasma case add NAME [FILTERS] [--spec JSON|FILE]
plasma case note NAME TEXT
plasma case timeline NAME
plasma case report NAME [--out FILE]
plasma case seal NAME
plasma case verify NAME

plasma detect validate --rules FILE
plasma detect test [--cases FILE]
plasma detect diff --old FILE --new FILE
plasma detect replay --events FILE [--rules FILE] [--max-rows N]

    Typed, bounded investigation over the local JSONL store. query refuses unknown fields; tree uses only explicit pid/ppid edges; summarize returns a capped digest. A case collects selected rows and notes, renders a report and seals every artifact with SHA-256. detect compiles rule regexes, compares rule sets and replays chains over a capture. See Investigation.

    drift¶

    plasma drift record QUESTION [--root PATH] [--canary ACCOUNT...]
plasma drift score  QUESTION [--root PATH]
plasma drift list   [--root PATH]

    record snapshots; score diffs (exit 2 on drift, 1 on collection error).

    chain / store / coverage¶

    plasma chain score --events FILE [--window SECONDS] [--max-rows N]
plasma store rotate  --events FILE [--max-mb N] [--keep N]
plasma store compact --events FILE [--out FILE]
plasma store stats   --events FILE
plasma coverage [--sensors DIR]

    Chains scan the tail; store commands keep the diary bounded; coverage reports ATT&CK coverage incl. blind spots.

    observe¶

    plasma observe attest|sketch|edges|explain|pslogs|attackmap|...

    Read-only self-knowledge questions (identity surface, logon edges, network edges, PowerShell logs, attack map). attest includes the blind check.

    Desk-side commands¶

    fleet¶

    plasma fleet pull      --inventory FILE --case NAME [--cap N] [--window SECONDS] [--canary ACCOUNT...]
plasma fleet correlate --case NAME [--window SECONDS]
plasma fleet report    --case NAME

    Correlates lateral hops, shared indicators, canaries and blind hosts.

    estate¶

    plasma estate build    --events FILE [--out FILE] [--window MIN] [--max-rows N] [--host NAME] [--role ROLE]
plasma estate merge    (--ledgers FILE... | --dir DIR) --out FILE [--max-age MIN]
plasma estate findings --ledger FILE [--threshold N] [--baseline FILE] [--max-identity-age MIN]
plasma estate sync     --inventory FILE --out-dir DIR [--window MIN] [--workers N]
                       [--threshold N] [--max-age MIN] [--role ROLE]
                       [--baseline FILE] [--max-identity-age MIN] [--loop] [--interval SECONDS]
plasma estate status   --ledger FILE

    The estate edge ledger: each host reduces its own store to a small hash-sealed identity ledger, the desk merges the newest ledger per host and correlates user/source/hash fan-out, stale hosts and new host edges. Coverage findings (estate_identity_blind, estate_identity_unverified, estate_no_telemetry, estate_kerberos_blind, estate_identity_stale) separate a quiet estate from a blind or unverified identity feed. --max-identity-age defaults to 180 minutes. sync is the continuous form; --loop runs until stopped. See Estate edge ledger.

    actuate / playbook¶

    plasma actuate apply <action> [--target T] --reason TEXT [--apply --plan ID]
plasma actuate undo  --id ID [--apply]
plasma actuate journal [--last N]
plasma actuate apply --list
plasma playbook list
plasma playbook apply <name> [--target T] --reason TEXT [--apply --plan ID]
plasma playbook undo  --id ID [--apply]

    --apply requires --plan from a seen dry-run of the same action + target.

    enforce¶

    plasma enforce run [--root DIR] [--apply | --dry-run]
plasma enforce status
plasma enforce pending
plasma enforce approve --id ID [--apply]

    Tier 0 prevention: findings become allowlisted, reversible containment. Armed by default but narrow: snapshot + kill_process at score 9+, a 2-action per-run cap and a 30-minute cooldown; isolation and every other action require approval. The policy still gates each action. The installer registers PlasmaWatch, which runs plasma watch once --enforce at boot and every 5 minutes.

    protect¶

    plasma protect status
plasma protect protected
plasma protect arm [--apply-prevention --reason TEXT]
plasma protect disarm [--reason TEXT]

    Inspect or change the measured posture. arm writes the measured enforcement block; disarm sets enabled: false and mode: "dry-run". protected lists the services, processes, accounts and paths the response layer refuses to touch.

    prevent¶

    plasma prevent status
plasma prevent posture
plasma prevent cfa [--mode off|audit|block] [--apply --plan ID --reason TEXT]
plasma prevent network [--mode off|audit|block] [--apply --plan ID --reason TEXT]
plasma prevent driver-blocklist [--off] [--apply --plan ID --reason TEXT]
plasma prevent applocker [--mode audit|enforce] [--allow-path P]... [--apply --plan ID --reason TEXT]
plasma prevent egress --allow IP[:PORT]... [--apply --plan ID --reason TEXT]
plasma prevent asr --ids GUID[,GUID] [--action Audit|Enabled|Disabled] [--apply --plan ID --reason TEXT]
plasma prevent lsa [--off] [--apply --plan ID --reason TEXT]
plasma prevent rollback --id ID [--apply]

    Tier 1 prevention through Windows enforcement points. Every control is dry-run first, plan-gated, verified, journaled and undoable by id. AppLocker defaults to audit; egress requires an explicit allowlist; ASR needs Defender; LSA takes effect after a reboot. posture is read-only and reports WDAC, Controlled Folder Access, Network Protection, the vulnerable driver blocklist, ASR counts and tamper protection. cfa, network and driver-blocklist are opt-in, plan-gated and rollbackable; WDAC stays read-only.

    update¶

    plasma update check [--repo OWNER/NAME] [--token-env VAR]
plasma update apply [--bin PATH] [--root PATH] [--allow-unsigned]
plasma update auto [--root PATH] [--ring canary|broad|rollback]
                   [--check-only] [--force] [--allow-unsigned] [--no-notify]

    Anonymous against the public repo; signature-pinned. update auto is the measured self-update path: it respects the deployment ring, the 02:00–05:00 maintenance window, the 24-hour canary hold, the kill switch and one-at-a- time locking. The installer registers PlasmaUpdate to run it daily; --no-autoupdate disables it.

    control (agent trust layer)¶

    plasma control policy show|set
plasma control approvals list|approve|deny
plasma control audit tail|verify
plasma control killswitch status|on|off
plasma control tenants list|add|remove

    policy set accepts --autonomy assist|supervised|autonomous, --deny, --allow, --max-actions, --max-hosts and --allow-critical. audit verify exits 2 if the hash chain is broken. Approvals are single-use and bound to the tool and argument hash.

    mcp¶

    plasma mcp serve [--root PATH]

    MCP over stdio. Twenty typed tools; mutating tools return a dry-run plan and approval reference, never an execution. See Agent-native operation.

    serve¶

    plasma serve [--host 127.0.0.1] [--port 9999] [--api-key KEY]
             [--api-key-file FILE] [--root PATH] [--read-only]
             [--tls-cert FILE --tls-key FILE] [--timeout SECONDS]
             [--max-body BYTES] [--max-output BYTES] [--no-audit] [--quiet]

    The full CLI over an authenticated HTTP API. POST /v1/exec takes an argv list and runs it through the real parser; GET /v1/commands returns the command tree. The default bind is loopback; a non-loopback bind refuses the known default key plasmaplasma unless --allow-insecure-default-key is set. Use --api-key-file or PLASMA_SERVE_API_KEY in production. --read-only refuses every mutating command. Every call is written to <root>/serve/audit.jsonl. See HTTP API.
