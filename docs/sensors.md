# Sensors

## Sysmon — the kernel flight recorder

The foundation. Plasma provisions the official Sysmon build with a baseline
configuration and depends on its Event Log channel for process, network,
DNS and file telemetry.

- **Install**: downloaded by the intelligent installer, EULA accepted
  non-interactively (`-accepteula`).
- **Health**: `sysmon_service` (service running) and `sysmon_feed` (newest
  Sysmon event within 60 minutes) are part of `plasma health`.
- **Read**: via Event Log API and WHIDS; never by loading a driver of our own.

## WHIDS — written suspicion rules

[WHIDS 1.7.0](https://github.com/0xrawsec/whids) reads Sysmon and applies
**gene rules** — written expressions with an ATT&CK technique and a
criticality of 0–10. Plasma ships ten baseline rules:

| Rule | Score | Looks for |
|---|---|---|
| LOLBin Certutil | 7 | `certutil -urlcache` / `-decode` |
| Office Spawning Shell | 8 | winword/excel/outlook → cmd/powershell/wscript/cscript/mshta |
| SAM Hive Dump | 9 | `reg save hklm\sam` / `hklm\system` |
| Bitsadmin Transfer | 7 | `bitsadmin /transfer`, `/create` |
| Mshta Network | 8 | `mshta` with an HTTP(S) or UNC target (local paths excluded) |
| Rundll32 JS | 8 | `rundll32 javascript:` / `url.dll` / `RunHTMLApplication` |
| Net Account Add | 8 | `net user … /add`, `net localgroup … /add` |
| Encoded Cmd | 6 | `-enc`, `-ec`, `-EncodedCommand` |
| Scheduled Task Create | 6 | `schtasks /create` |
| Wmic Process Call | 7 | `wmic process call create` |

WHIDS runs **detect-only**: every action band is configured to `report`.
The v1.7.0 engine has no response verbs at all; Plasma keeps it that way on
purpose. Alerts land in `C:\Program Files\Whids\Logs\Alerts\` and are
normalized into the events store by `plasma whids pull`.

Pushed IOCs live in `Database\Rules\plasma-iocs.gen` and are regenerated by
`plasma whids push --apply` from high-confidence events.

## Identity — the Security channel

Audit events (4624/4625) are written by LSA directly into the Security
channel and are **not** re-emitted to realtime ETW sessions (proven on a
live host: a 75-second trace saw zero of them). Plasma therefore reads the
channel through the Event Log API:

```powershell
plasma identity pull --events C:\ProgramData\Plasma\data\events.jsonl --since 60
```

Each record becomes `kind: "auth"` with `user`, `dest_ip` (source address),
logon type, workstation, process basename and a UTC timestamp. Success is
`info`; failure is `medium` (score 0.5). Duplicates are removed by hash.

## ETW tap — the on-demand microphone

`plasma-tap.exe` (krabsetw) opens a trace session for a bounded window,
matches events against 31 rules, prints JSONL matches, and exits. No
service, no persistence, no standing driver of ours.

```powershell
plasma tap list                                   # rules
plasma tap selftest                               # compile + self-check
plasma tap run --providers powershell,dns,wmi --for 10s --max-matches 500
```

Providers: PowerShell (4104 script blocks), WMI activity, DNS client,
.NET runtime, Schannel, and Security-Auditing aliases. Rules are
case-insensitive substring matches on a named field, with `event_id = 0`
meaning "any". Notable rules include `Invoke-Mimikatz`, `MiniDumpWriteDump`,
`amsiInitFailed`, `IEX(New-Object Net.WebClient`, `Invoke-Shellcode`,
`__EventFilter`/`ActiveScriptEventConsumer`, ngrok and trycloudflare
queries.

Tap exit codes are meaningful: `3` means the session could not be started
(no admin rights or ETW unavailable) — the tap never pretends.

## Deep persistence probe

Sysmon sees persistence *changes*; `plasma deep persistence` sees the
whole picture:

```powershell
plasma deep persistence --json-out C:\ProgramData\Plasma\deep-persistence.json
```

It reads, in one bounded pass:

- registry Run / RunOnce keys (HKLM and HKCU),
- services with their `ImagePath`, start mode and account,
- scheduled-task actions and triggers (Microsoft paths excluded),
- IFEO `Debugger` hijacks,
- Winlogon `Shell` / `Userinit`,
- WMI event filters, consumers and binding count.

Every binary path found gets an Authenticode check (bounded, capped). An
item is flagged `suspect` when it is **unsigned and outside `C:\Windows`**.
That flag is evidence for a human — never an automatic action.

## Sensor-of-sensors

The health checks that watch the watchers:

| Check | Meaning |
|---|---|
| `sensor_heartbeat` | the events diary is still being written (newest row < 24h) |
| `rdp_hardening_drift` | `fDenyTSConnections=0` and a sane `SecurityLayer` — the lockout-incident checks |
| `tap_sidecar` | the ETW tap binary is present |
| `whids_service` / `sysmon_feed` | the detection stack is alive |
