The problem

EDR shouldn’t be able to lock you out.

Three assumptions in conventional EDR and SIEM create cost, opacity and risk. Plasma inverts each one.

The lake problem

Stream every event to a central lake and you pay for storage, latency and privacy — then hope the pipeline never drops the one event that mattered.

costlatencydata gravity

The trust problem

A cloud model decides what is suspicious. You cannot read its menu, reproduce its selection, or verify it did not hallucinate an answer.

opaqueunreproducible

The response problem

A vendor action fires and you cannot see the plan, the payload, or the undo. An EDR that removes remote access can take the estate down with it.

irreversibleopaque
Architecture

Four planes. One contract.

Sensors collect locally. A strict JSONL contract is the only seam. A frozen model selects from a closed menu. The desk pulls answers — there is no standing server.

Agent-native

Autonomy with a leash.

The harness investigates and proposes. The policy engine decides. The approval queue gates the dangerous calls. The ledger remembers everything — harness, model, prompt digest, arguments, policy, approval and outcome.

Autonomy is a setting

Assist — approve everything. Supervised — auto low/medium, approve containment. Autonomous — act within policy, humans on the loop, kill switch ready. Start supervised; earn autonomous.

plasma control policy set --autonomy supervised

Evidence, not assurances

CBN, NDPA, PCI DSS and ISO 27001 control matrices from real state; CycloneDX SBOM; a safety case with the eval result; a redacted support bundle.

plasma evidence export --framework cbn ndpa pci iso27001
The model is never in the kill path. Telemetry is untrusted data, tool arguments are schema-validated, and mutating MCP tools return a plan — not an execution.

Response

Nothing changes without a plan you have seen.

Thirteen allowlisted actions. Dry-run is the default. Applying requires the id of a prior dry-run of the same action and target. Every applied action is journaled and reversible where possible.

Dry-run

Build the exact payload without touching the host. The CLI prints what would run and whether it can be undone.

default · no side effects

Plan id

A deterministic id binds the action, target and payload digest. It is the only key that unlocks execution.

digest must match

Apply

Re-run the same command with --apply --plan <id>. A mismatch or missing plan is refused.

human decision

Journal + undo

The action is recorded with its undo payload. Reverse it last-first; actions that cannot be undone say so first.

reversible by design

Playbooks

contain-user and isolate-box are fixed sequences applied as one plan-gated unit. The first failing step aborts the rest; undo walks the succeeded steps in reverse.

isolate-box keeps RDP 3389 and WinRM 5985 open on purpose.

What it will not do

No free-form command execution. No deleting a protected account or service. No silent unisolate. No response in detect-only mode until an operator supplies the plan id.

an EDR that cannot remove remote access is a liability.

Deployment

One binary. Or one MSI. Your GPO.

The same install path runs interactively, through the MSI, or from Group Policy. The node records exactly which sensors are active and why.

01 · DOWNLOAD

Signed release

Grab the exe or MSI. SHA256SUMS and a pinned Authenticode signer gate every update.

02 · INSTALL

Intelligent mode

The installer verifies the manifest, decides FULL or MINIMAL, provisions Sysmon and WHIDS where feasible.

03 · CONVERGE

Updates repair

Every install re-stages config, rules, the WHIDS binary and the Sysmon config from the bundle — no stale config survives.

04 · VERIFY

Health + watch

plasma health and plasma watch once close the loop; the watchdog keeps WHIDS alive.

MSI + GPO

Silent install to a custom root, deployed by Group Policy. The MSI runs the same installer payload as the exe.

msiexec /i plasma.msi /qn PLASMA_ROOT=C:\ProgramData\Plasma

Self-healing

WHIDS hangs are healed by a SYSTEM watchdog every two minutes. Sysmon and WHIDS service state are visible in every health verdict.

Signed updates

Updates verify SHA256SUMS, then the Authenticode signer against thumbprints baked into the installed binary. Unsigned updates are refused.

DTrace

A microscope you pick up, then put down.

DTrace is the third detection layer: kernel and syscall instrumentation for one question, for a bounded window. Reviewed scripts only, normalized into the same contract.

endpoint · trace 
# is it there, and is it enabled?
plasma trace check

# install the Microsoft package + boot setting
plasma trace provision
→ reboot_required: true

# compile-only check of every reviewed script
plasma trace selftest

# bounded run: window + row cap, then killed
plasma trace run syscall-errors \
  --events C:\ProgramData\Plasma\data\events.jsonl \
  --for 5s --max-rows 200

Reviewed, not free-form

Three shipped scripts: syscall-errors (T1106), process-create (T1059), etw-kernel-process (T1057). The loader refuses system(), unknown providers and rows without the plasma| marker.

Bounded by construction

Wall-clock window (1 s–5 m), row cap, optional raw capture, content-hash dedupe. The tracer excludes itself so it never fills the store with its own syscalls.

Estate-honest

Microsoft’s current package is labelled 2.0 but still reports Sun D 1.13.1. Readiness is capability-based: installed + enabled is ready. Scripts emit tid because pid is not portable across Windows builds.

Security model

Read-only first. Deterministic always.

The design assumes the box may be compromised and the operator may be wrong. Both are handled with evidence and gates, not promises.

01

Read-only first

Nothing changes on a host until a human passes --apply --plan <id>.

02

Deterministic detection

Rules and chains are written code. The model selects probes; it never decides guilt.

03

Bounded collectors

Every collector has a time window, row cap and size cap. No unbounded tail.

04

Local by default

Events stay on the host. The desk pulls only what it needs, only when asked.

05

Reversible response

Every applied action carries a journal entry and an undo payload, or says up front that it cannot.

06

Verified supply chain

Manifest digests, SHA256SUMS, and pinned Authenticode signers. An unsigned update is refused.

Known limits

Not a kernel driver of its own. No memory scanning. Coverage gaps are named. DTrace needs a host that supports it. There is no central console by design.

Questions

The honest answers.

Is this a replacement for commercial EDR?

It is a different trade. Plasma trades the vendor console and the cloud lake for on-box evidence, a closed probe menu, and reversible actions. For commodity malware blocking at scale, a commercial EDR may still be the right tool. For identity-led investigation, lateral movement, LOTL and root-cause on boxes you administer, Plasma is deliberately better at answering “what happened here?”

Does any data leave the host?

Not by default. Sensors write a local JSONL store. The desk pulls a bounded tail over WinRM or SSM only when an operator runs fleet pull. There is no standing server and no telemetry endpoint.

Can the model hallucinate a verdict?

It can only select from ten frozen probes. If no probe fits, it refuses with a structured error. The probes are deterministic code; the model is a router, not a judge.

Why is WHIDS detect-only?

Because an EDR that can remove remote access can lock its operators out. Every action band is set to report. Response lives in actuate, behind a human plan gate and an undo journal.

What happens when WHIDS hangs?

A SYSTEM scheduled task runs plasma whids ensure every two minutes. A hung StartPending is force-stopped and started again; every action is logged. Crashes are also covered by SCM failure actions.

How is an update trusted?

Two anchors. The release’s SHA256SUMS must match the downloaded exe, and the exe’s Authenticode signer must match a thumbprint baked into the installed binary. Failing either refuses execution.

What does “lake-less” mean in practice?

No central event lake. Detection, correlation and the model run where the events are. The desk is a pull-based reader with case files, not a server that stores everyone’s diary.
