The problem

EDR shouldn’t be able to lock you out.

Three assumptions in conventional EDR and SIEM create cost, opacity and risk. Plasma inverts each one.

The lake problem01

Every event, sent away

Stream every event to a central lake and you pay for storage, latency and privacy — then hope the pipeline never drops the one event that mattered.

costlatencydata gravity
The trust problem02

A verdict you cannot read

A cloud model decides what is suspicious. You cannot read its menu, reproduce its selection, or verify it did not hallucinate an answer.

opaqueunreproducible
The response problem03

An action with no undo

A vendor action fires and you cannot see the plan, the payload, or the undo. An EDR that removes remote access can take the estate down with it.

irreversibleopaque

Baseline

Learn the host. Ship counts, not logs.

A profile is what one host knows about its own normal — images, parent→child edges, identity pairs, registry and file families, command shapes, and robust hourly volume. Tens of kilobytes. No event rows, no raw command lines.

Compact by construction

Top-K tables and 24 robust statistics per entity. A thousand hosts is megabytes at the desk, not a lake. Every profile carries a SHA-256 integrity hash.

~150 KB per host · integrity verified

Scores you can argue with

Edge rarity, first-seen keys, robust daily volume and optional estate rarity fuse into 0–10, with the observed and total counts behind every component. A cold profile returns no score.

Causal traces

PID/PPID spans rebuild one host's process trees, with PID-reuse handling and optional edge-rarity scoring. RDP and SMB hops start a new tree by design.

Plugins

Extend it without forking it.

Sensors, detectors and responders are bounded external processes with a signed manifest and an NDJSON contract — the same pattern Sysmon and WHIDS already use. Write one in any language, sign it, install it, and the core still owns validation, the event store and the plan gate.

Four kinds

Sensor emits events. Detector emits findings over a bounded tail. Responder declares named actions. Exporter is reserved for plugin-driven sinks.

sensordetectorresponder

Manifest, not import

One plugin.json, a payload hash and an Ed25519 signature. Entrypoints cannot escape the plugin directory; nothing is auto-enabled.

signed · hashed · any language

Records are typed, capped, redacted, stamped with the plugin identity and deduplicated. Ten invalid records quarantine the run. The plugin never writes the store.

Response

Nothing changes without a plan you have seen.

Thirteen allowlisted actions. Dry-run is the default. Applying requires the id of a prior dry-run of the same action and target. Every applied action is journaled and reversible where possible.

01 · Dry-run

Plan first

Build the exact payload without touching the host. The CLI prints what would run and whether it can be undone.

default · no side effects

One key

A deterministic id binds the action, target and payload digest. It is the only key that unlocks execution.

Playbooks

contain-user and isolate-box are fixed sequences applied as one plan-gated unit. The first failing step aborts the rest; undo walks the succeeded steps in reverse.

isolate-box keeps RDP 3389 and WinRM 5985 open on purpose.

What it will not do

No free-form command execution. No deleting a protected account or service. No silent unisolate. Automatic containment exists, but only under a written policy and, for high-impact actions, a human approval.

an EDR that cannot remove remote access is a liability.
Prevention

Two speeds of stopping things.

Containment reacts in seconds and can be reversed. Enforcement points stop the behaviour before it starts. Containment is armed by default but deliberately narrow; enforcement points are audit-first and journaled.

Tier 0react

Containment

plasma enforce turns findings into allowlisted, reversible actions. Injection findings capture one host snapshot and then kill the accessing process; a tripped canary queues host isolation for approval. Score floor, per-run cap, per-target cooldown, approval queue and kill switch are enforced in code.

applied in the estate drill: 1 kill · 1 isolation held for approval
Tier 1prevent

Enforcement points

plasma prevent configures what Microsoft already enforces: AppLocker, firewall egress, Defender ASR, LSA, Controlled Folder Access, Network Protection and the driver blocklist. Each control is previewed, plan-gated, verified and rollbackable by journal id. WDAC stays read-only because a bad boot-time policy is not safely automated.

drill: AppLocker audit apply/rollback; CFA audit → block → rollback

Armed by default, narrow

Automatic containment is limited to snapshot + kill_process at score 9+, with a 2-action per-run cap and a 30-minute cooldown. Isolation and every other action require approval. plasma protect disarm turns it off.

Bounded blast radius

Snapshot before kill, per-run cap, per-target cooldown and a kill switch. WinRM, RDP, WHIDS, Sysmon, LSASS and Administrator are refused in code.

No Plasma driver

Inline blocking is delegated to Microsoft's signed enforcement points. Plasma owns policy, evidence and rollback — and says so plainly.

Estate ledger

Continuous cross-host correlation without a lake.

Each host reduces its own store to a small hash-sealed count ledger. The desk replaces the previous copy, merges the newest ledger per host, and raises identity fan-out, shared sources, shared file hashes and stale hosts — in seconds, at estate scale.

Counts leave. Events do not.

A ledger holds accounts, first/last seen, bounded source addresses, logon types, user>process pairs and hashes. No command lines, no file paths, no event rows. Caps are absolute: 200 users, 10 sources per user, 200 process pairs and 256 KiB per host.

Every ledger carries a SHA-256 over its canonical body; merge and status refuse a modified file. This is integrity, not a signature — the trust boundary is the desk ACL and WinRM. The desk keeps one current ledger per host and replaces it on each pull.

replace-in-place · current snapshot · no central index

Five findings that need more than one box

User fan-out scores 9 only when a source address links at least two appearances; otherwise 7, flagged as a same-name pattern to verify. Source fan-out catches one address touching many hosts. Hash fan-out scores a shared file hash on many hosts at 8. Stale host is a finding, not a silent gap. New host edge compares against an optional baseline.

One account on fifty machines in an hour is exactly the question a per-endpoint diary cannot answer alone.

Ten shipped scripts: syscall-errors (T1106), process-create (T1059), etw-kernel-process (T1057) and seven injection probes — RWX, remote thread, APC, hijack, hollow, section and remote write. The loader refuses system(), unknown providers and rows without the plasma| marker.

Bounded by construction

Wall-clock window (1 s–5 m), row cap, optional raw capture, content-hash dedupe. The tracer excludes itself so it never fills the store with its own syscalls.

Estate-honest

Microsoft’s current package is labelled 2.0 but still reports Sun D 1.13.1. Readiness is capability-based: installed + enabled is ready. Scripts emit tid because pid is not portable across Windows builds. Field check: 10/10 compile; EID 10/17/18 observed; the section predicate went from 12 rows/5 s to 0 after the arg1 fix.

HTTP API

The whole CLI, behind one key.

plasma serve exposes every command, flag and default over an authenticated HTTP API — an alternative to WinRM or SSH. One argv endpoint, a command tree, read-only mode, TLS, per-call timeouts and an audit log.

endpoint
# start the API (default 127.0.0.1:9999)
plasma serve --port 9999 \
  --api-key-file C:\ProgramData\Plasma\serve.key

# run any CLI command
curl -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -X POST http://HOST:9999/v1/exec \
  -d '{"argv":["health"]}'

# discover the command tree
curl -H "Authorization: Bearer <key>" \
  http://HOST:9999/v1/commands
routes
GET  /healthz        liveness (no auth)
GET  /v1/version     version + runtime
GET  /v1/commands    full CLI tree (207 commands + root, with help metadata)
POST /v1/exec        run one CLI argv
Narrow by design. The argv is parsed by the real CLI parser before anything runs. --read-only refuses every mutating command, including any --apply. Each call runs in a child process with a hard timeout, a 1 MiB request cap and an 8 MiB output cap. Every call lands in <root>/serve/audit.jsonl; the key is never logged.

API-key auth

Bearer or X-API-Key, constant-time compare. The default bind is loopback; a non-loopback bind refuses the known default key. Production uses --api-key-file or PLASMA_SERVE_API_KEY.

no key in the audit log

Read-only mode

--read-only refuses install, apply, undo, policy changes, kill switch, prevention, fleet writes and every other state change. Reads and dry-runs remain.

observer endpoint

TLS + audit

--tls-cert and --tls-key wrap the listener. Every call is recorded with remote address, key id, argv, exit code and duration.

alternative to WinRM/SSH
OpenAPI 3.1. The machine-readable spec is at /openapi.json; a self-contained HTML reference is at /docs. Both are unauthenticated. The spec covers the four routes, both auth schemes and the error envelopes.
Security model

Read-only by default. Gated when it acts.

The design assumes the box may be compromised and the operator may be wrong. Both are handled with evidence and gates, not promises. Containment is armed but narrow; prevention is never implicit.

01

Read-only by default

Collectors read. Mutations happen only in the response and prevention planes, after a plan you have seen — or under a written enforcement policy you enabled.

02

Deterministic detection

Rules and chains are written code. The model selects probes; it never decides guilt.

03

Bounded collectors

Every collector has a time window, row cap and size cap. No unbounded tail.

04

Local by default

Events stay on the host. The desk pulls only what it needs, only when asked.

05

Reversible response

Every applied action carries a journal entry and an undo payload, or says up front that it cannot.

06

Verified supply chain

Manifest digests, SHA256SUMS, and pinned Authenticode signers. An unsigned update is refused.

Tested on a live estate

Two Windows Server hosts: signed updates, 25 baseline + 259 Sigma rules, behavioural profiles, Sysmon FileDelete, canaries, fleet correlation, AppLocker/egress apply-and-rollback drills, DTrace runs, Atomic Red Team and TTPForge/ForgeArmory simulations — plus the field WHIDS dump-tree hang, recovered and permanently bounded.

Questions

The honest answers.

Does Plasma block anything?

Yes — containment is armed by default, but narrow. enforce captures a host snapshot and then kills the accessing process at score 9+; host isolation and every other action wait for approval. prevent configures AppLocker, firewall egress, Defender ASR, LSA, CFA, Network Protection and the driver blocklist; it is audit-first and opt-in. plasma protect disarm turns automatic containment off. Plasma ships no kernel driver of its own.

Is this a replacement for commercial EDR?

It is a different trade. Plasma trades the vendor console and the cloud lake for on-box evidence, a closed probe menu, and reversible actions. For commodity malware blocking at scale, a commercial EDR may still be the right tool. For identity-led investigation, lateral movement, LOTL and root-cause on boxes you administer, Plasma is deliberately better at answering “what happened here?”

Does any data leave the host?

Not by default. Sensors write a local JSONL store. The desk pulls a bounded tail over WinRM or SSM only when an operator runs fleet pull. There is no standing server and no telemetry endpoint.

Can the model hallucinate a verdict?

It can only select from ten frozen probes. If no probe fits, it refuses with a structured error. The probes are deterministic code; the model is a router, not a judge.

Why is WHIDS detect-only?

Because a sensor that can remove remote access can lock its operators out. Every WHIDS action band is set to report. Action lives in Plasma: actuate for manual response, enforce for policy-gated containment, prevent for Windows enforcement points — all journaled and reversible.

What happens when WHIDS hangs?

A SYSTEM scheduled task runs plasma whids ensure every two minutes. A hung StartPending is force-stopped and started again; every action is logged. Crashes are also covered by SCM failure actions.

How is an update trusted?

Two anchors. The release’s SHA256SUMS must match the downloaded exe, and the exe’s Authenticode signer must match a thumbprint baked into the installed binary. Failing either refuses execution.

What does “lake-less” mean in practice?

No central event lake. Detection, correlation and the model run where the events are. The desk is a pull-based reader with case files, not a server that stores everyone’s diary.
